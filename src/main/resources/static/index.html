Unidad II - Aspectos formales

Gramáticas · Regex · Autómatas

Gramática real de Compila26

Notación EBNF utilizada por el parser descendente recursivo.

programa    → sentencia*
sentencia   → declaracion | asignacion
declaracion → 'int' IDENTIFICADOR ';'
asignacion  → IDENTIFICADOR '=' expresion ';'
expresion   → suma
suma        → termino (('+' | '-') termino)*
termino     → factor (('*' | '/') factor)*
factor      → NUMERO | IDENTIFICADOR | '(' expresion ')'

Lenguajes intermedios

Compila26 conserva esta representación independiente para que un backend futuro pueda consumirla sin alterar el análisis del lenguaje.

Resultado real de Compila26

Código de tres direcciones

int x;
x = 10 + 5 * 2;
10 + 5 * 2↓
t0 = 5 * 2
t1 = 10 + t0
x = t1

Cada instrucción expresa una operación simple. Los temporales conservan resultados intermedios durante la traducción.

Anatomía de una instrucción

Ejemplo didáctico fijo basado en una instrucción real. La API actual devuelve la versión textual, no sus campos estructurados.

=

Temporales

5 * 2↓ 10 + t0↓

t0, t1, … son creados por el generador; no representan registros físicos ni direcciones.

Precedencia: el AST decide el orden

ASIGNACION
├── ID: x
└── OPERADOR: +
    ├── NUMERO: 10
    └── OPERADOR: *
        ├── NUMERO: 5
        └── NUMERO: 2
→ 
t0 = 5 * 2
t1 = 10 + t0
x = t1

El generador no vuelve a decidir la precedencia: recorre primero la multiplicación, ya representada como subexpresión de la suma.

8.2

Declaraciones

int x;↓DECLARACION: int└── ID: x↓Tabla de símbolosx : int

Declaración

int x;

Introduce el identificador y su tipo.

Resultado actual: x : int en la tabla.

Asignación

x = 10;

Asocia un valor con una variable declarada.

Intermedio actual: x = 10.

En el modelo intermedio actual de Compila26, una declaración aislada no genera una instrucción de tres direcciones. No es una regla universal.

Direccionamiento

Determina cómo una instrucción localiza o accede a un dato.

No se presentan modos de direccionamiento ni direcciones de una arquitectura concreta.

Asignación estática y dinámica

Compila26 solo posee int; no tiene objetos, new, arrays dinámicos, funciones ni parámetros. La asignación dinámica no se implementa aquí.

El caso especial de la multiplicación

Una máquina podría ofrecer multiplicación directa, carecer de ella, requerir varias instrucciones o necesitar una rutina. Esta Parte 1 no decide cuál será el caso.
